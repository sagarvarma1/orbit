Features

The workflow you know, without the lock-in.

Everything between git push and a live URL, on hardware you control.

Git push to deploy

A GitHub App delivers pushes instantly. Builds stream live logs to the dashboard as they run.

Preview URLs

Every deployment and every branch gets its own URL, and pull requests get a comment linking to it.

Instant rollback

Deployments are immutable. Rolling back moves a pointer, so it takes milliseconds, not a rebuild.

Custom domains + HTTPS

Point DNS at your server and certificates are issued automatically on the first request.

Serverless functions

Files in /api become endpoints, with warm instances and an edge cache for s-maxage.

vercel.json compatible

Redirects, rewrites, headers, build settings and function config work as written.

Next.js, server-rendered

SSR, route handlers and server actions with no config changes. Vite, Astro and plain HTML work too.

Isolated builds

Each build runs in a throwaway Docker container with CPU and memory limits, and a dependency cache.

Commit checks

Builds report back to GitHub as commit statuses, so a failed deploy shows up on the pull request.

How it works

Builds are immutable. Domains are pointers.

A build produces an artifact that never changes. Production, branches and custom domains are just names that point at one, which is why previews are free and rollbacks are instant.

Bring your project

Already on Vercel? Your config comes with you.

Orbit reads vercel.json: output directory, build commands, redirects, rewrites, headers, and per-function memory, duration and included files. americantimeuse.com moved over without a single change.

  • Node-style (req, res) and Web Request → Response handlers
  • __dirname and includeFiles for functions that read data
  • Cache-Control: s-maxage responses cached at the edge
vercel.json
{
  "outputDirectory": "dist",
  "cleanUrls": true,
  "functions": {
    "api/*.js": {
      "includeFiles": "dist/data/**",
      "memory": 1024
    }
  },
  "rewrites": [
    { "source": "/hello/:name", "destination": "/api/hello" }
  ]
}

Self-host

Live in about ten minutes.

Any Ubuntu server with 2 GB of RAM works. Orbit runs as a handful of Docker containers.

  1. 1

    Point a domain at your server

    One wildcard record. Every project and preview becomes a subdomain of it.

    A  *.your-domain.dev  →  your server's IP
  2. 2

    Run the installer

    It installs Docker if needed, asks for your domain and starts everything.

    curl -fsSL https://raw.githubusercontent.com/sagarvarma1/orbit/main/install.sh | sudo bash
  3. 3

    Connect GitHub and deploy

    Open the dashboard, create the GitHub App in one click, pick a repository and press Deploy.

Honest scope

What Orbit doesn't do yet.

  • All of Next.js. Server rendering works; ISR, edge middleware and image optimization are next.
  • Multiple regions. One server serves everything, so visitors far away wait longer.
  • Teams. One admin account per instance for now.
